# 신규 캐릭터 등록 절차 (char-add)

니케 데미지 계산기에 신캐가 들어오는 전체 경로. `char-add` 스킬이 담당하며,
각 단계가 끝날 때마다 결과 보고 후 다음 진행 여부를 확인한다(자동 연쇄 없음).

## 진입점 — 캐릭터 상태가 시작 단계를 정한다

| 상태 | 시작 단계 |
|---|---|
| 출시 전, 스킬 카드 이미지만 공개됨 | **0P** — 카드 전사 |
| 출시됐는데 블라블라 CDN에 아직 없음 | **0P** — 카드 전사로 선행 등록 |
| 블라블라 CDN에 있음(스크랩 가능) | **0** — 게임 데이터 수집 |
| 프리뷰로 등록됐는데 CDN에 떴음 | **R** — 정식 전환 |
| 데이터는 있는데 파싱만 안 됨 | **1~4** 이어서 |

## 단계별 흐름

| 단계 | 내용 | 산출물 |
|---|---|---|
| **0P** | 스킬 카드 이미지(Lv10 기준)에서 원문을 **요약·정규화 없이 그대로** 전사 | `scraper/preview_skills.json` 항목, `image/preview/` 카드, 미확정 목록 |
| **0** | 블라블라 CDN 수집 — 이름·ID 몰라도 `cdn_fetch.py --check`가 신규/변경 자동 탐지 | `nikke_scraped.json`, `parsed_nikke.json`, 이미지 |
| **1** | 시나리오 초안 — 원문으로 메카닉 이해, 검증 스쿼드 결정, 모호 점 질문 목록 | `context/scenarios/<이름>.md` |
| **2** | 스킬 파싱 — 원문 → 엔진이 이해하는 구조화 데이터 + 구현 필요 목록 | `parsed_skills.json` 항목 |
| **3** | 시나리오 보강 — 파싱 반영한 효과 표·타임라인·검증 체크리스트 | 같은 파일 |
| **4** | 구현·검증 — 엔진 코드 + 테스트 + 골든 스냅샷 회귀 + doclint | `spec.ts`·엔진·테스트 |
| **R** | 출시 후 정식 전환 — 스크랩 원문과 프리뷰 원문 대조, Lv1~9 계수 채움, 흔적 제거 | 정본 등록 |

## 자동으로 처리되는 것 vs 사람이 넣는 것

**자동 (수작업 없음):**
- 버스트 게이지 — 무기군 기본값(RL 2.8%/히트 등) 또는 CDN의 캐릭터 실값
- 무기 스펙 — 장탄 수·재장전·차지 시간·데미지 계수 (카드 우상단 or CDN)
- 캐릭터 초상·이미지 — 스크랩 시 자동 수집
- 신캐 감지 — `--check`가 CDN 대조로 신규/변경 목록 출력

**사람이 넣어야 하는 것 (데이터에 없는 값):**
- 스킬 레벨 1~9 계수 — 카드는 Lv10만 공개 (프리뷰 한정, 출시 시 자동 채워짐)
- `post_fire_delay`·`post_reload_delay` 실측 — RL/SR만, 기본값과 다를 때 유저 실측
- 특수 게이지 메커니즘 — 스킬로 게이지를 추가 충전하는 경우 실측 등록
- 모호한 메커니즘 — 대상 규칙, 해제 조건, 실행 순서 등은 유저 확인 필수

## 검증 게이트 (각 단계 종료 시)

- **전사 확인** — 전사 원문 통째로 보여주고 오독 확인받음
- **모호 점 질문** — 텍스트로 불명확한 것은 추측 금지, 묶어서 질문
- **해석 선언** — 대미지·실행순서·스케일링 관련 해석을 표면화해 유저 검토
- **회귀** — 엔진 테스트 + 골든 스냅샷 + `doclint` 통과 필수

## 프리뷰 → 정식 전환 (단계 R)

1. CDN에 캐릭터가 뜨면 `--check`가 신규로 보고 + doclint 검사 G가 실패로 알림
2. `preview_diff`로 프리뷰 원문 ↔ 스크랩 원문 대조
   - 일치 → 프리뷰 항목 제거, Lv1~9 채움, 정본 승격
   - 불일치 → diff 그대로 보고, 단계 2부터 재검토 (자체 판단 금지)
3. 프리뷰 흔적(파일·표기·이미지) 전부 제거 — 남기면 미검증으로 오인
